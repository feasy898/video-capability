## 1. owner 愿景的形式化重述

owner 的四句话不是四个偏好，是四个可判定的约束。把它们翻译成生产函数：

**生产函数**　`M = P(I, R, Θ)`，其中

- `I` = **意图**：owner 一次性提供的少量输入（参考图、题材、必须保留的物件、禁区）；对应 `INTENT.md:37` 的"我只提供意图，提供资源"。
- `R` = **资源**：卡1（2×V100S-32GB，SM70，仅 fp16）、积分钱包（MiniMax/Vidu/StepFun）、API 通道。红线：卡0 绝不占用（`INTENT.md:97`）。
- `Θ` = **冻结资产**：`thresholds.yaml` + 契约 JSON + 金标 + 夹具 + 判官配方。这是 `INTENT.md:50` 的 spec+eval 资产化范式在生产函数里的显式自变量——**改 Θ 必须重跑 eval，退化即回滚**（`overnight/vpipe/SPEC.md` §3「判定阈与准入线是两回事，勿混改」）。
- `M` = **成片**：ffprobe 口径上可交付的 mp4（竖版、h264+aac、时长 ±1s，`INTENT.md:89`）。

**流水线是 Θ 驱动的、有界确定性映射**，不是一次创作。`P` 的性质三条：

1. **分段廉价/昂贵**：同一条片子，构图/动作/时间/节奏这些"能被工件钉死"的工序先在零生成成本或近零成本层解决，昂贵的视频生成只负责渲染已经定好的东西。
2. **逐段可判定**：每一段结束时产出一个**客观工件**（分镜表、动作脚本、时间线、节奏轨、草稿片、QCReport），工件满足该段的机器可判门禁才允许进入下一段；不满足则回退到该段重做，不允许"整条重抽"。
3. **人类只确认工件，不裁决质量**：`INTENT.md:73` 明令"测试出来的结果由 agent 先检查，只有确实需要上升人类的才上升"，且人类介入形态被限定为"文字反馈 / 圈改 / 给参考"三种（`INTENT.md:88`）。因此检查点不是抽象的"审批"节点，而是**工序天然存在的、可被人类一眼判断对错的中间产物**——构图、动作、时间、节奏恰好都是人本来就要管的工作步骤，所以对应的工件（分镜图、动作脚本、时间线、节奏轨）就是人类本来就要确认的东西。

**目标函数不是"惊艳"，是"平庸但可接受"**。这把验收从"最大化质量"改成"零严重缺陷 + 覆盖率下限"：A 组（程序可检）召回 ≥99%、误报 ≤1%；B 组召回 ≥95%、误报 ≤15%；C 组类内召回 ≥80%、误报 ≤15%（`AI视频生产流水线方案.md` 表 2-1 口径），人工上升率 ≤20%。质量上限由所选模型档位给出，不再往上追。

## 2. 五大设计原则

**原则一：分层廉价/昂贵分工，不是"省钱的模型"，是"让工序在便宜的层被钉死"。**
便宜与昂贵的分界不是分辨率或模型强弱，而是**这一段的信息是否还需要被想象**。字幕、花字、排行榜、时长、节奏、混音、转场在 HTML/ffmpeg 里是纯函数，`hypit-svml-deepdive.md:43,76` 实测这些图层零调用费，付费请求只剩"2 条视频 + 9 张 2K 图"；反过来，构图与动作一旦交给视频大模型去"想象"，成本立刻从 ¥0 跳到按秒计费，且不可回归。因此每个工序必须先问：这一段能不能被降维成确定性层的一个函数？能，就不许下沉到生成层。依据同前两份调研 + `cheap-draft-and-programmatic-tools.md:105,265-266`。

**原则二：程序化合规门禁，而不是人工盯帧。**
owner 的不对称代价原则（`INTENT.md:30`：餐饮营销里变形食物是主动品牌伤害，误杀只损失一次生成机会；误杀率上限 25%、漏网率目标 0）是**方向性冲突，不是参数可调和的分歧**——DramaClaw 的门禁哲学恰是反的（`dramaclaw-deepdive.md:477-488`：`sketch_visual_gate.py` 原文「`unsure` is treated as pass … better to let a suspect cell through than to drop a good one onto the floor」）。两者都对，但只在各自代价结构下成立。所以本白皮书不采用任何一方的全局默认，而是要求**每个缺陷组显式声明它的不对称性参数**（`误杀代价 / 漏检代价` 比值 → 由 `thresholds.yaml` 单点配置，禁硬编码）。这一条同时否掉了"多 judge 合议投票解决一切"的想法：投票只能在同代价结构的缺陷组之间做。

**原则三：人类的环节要可替换，不可缺席。**
owner 说"即使 AI 做不到像人一样看清连续画面运动也没问题"——这句的正确工程翻译是：**时序/物理/叙事这类判断在当前技术条件下允许保留人工工位**，但不能保留"人肉盯 24 镜 × 33 帧"。仓内实测证据完全支持这个让渡：7 路 judge 在时序四类上召回全零（`工程方案v3.1.md:110`），J6v2 程序化时序检测器重建后 clip 召回也只有 0.625（`工程方案v3.1.md:157`）。于是结论是：**时序判断从"抽帧 VLM 判断"改成"程序化检测 + 人工只看程序标出的时间窗"**，人工成本从 O(镜数×帧数) 降到 O(候选时间窗数)。 DramaClaw 的 `emit_human_override.py`（`dramaclaw-deepdive.md:466`）把这个动作定义成 capture point 而非审批，是同一思路的可抄形态。

**原则四：可复现优于可惊艳。**
owner 的"平庸但可接受"不是降低要求，是**把要求从主观轴移到客观轴**。API 通道 seed 零控制力是硬实测：同 prompt+seed=42 两片帧 aHash 汉明均值 102.75/64bit，比无 seed 组（51.75）更不相似（`工程方案v3.md:38`）。所以"同一 prompt 重跑得到同一片子"在任何 API 档位都是**假承诺**；能承诺的只有三档：确定性层（ffmpeg 合成同参数二遍 md5 一致，`工程方案v3.1.md:218` 实测 `289f96f3…`）、本地生成层（同种子帧级一致，`overnight/vpipe/SPEC.md` §2.1）、API 层（参数级/提交参数级复现，`SPEC.md` §2.2「同指纹重提交必然新样本」）。**任何排产表不许把 API 产物写进 md5 回归基线。**

**原则五：检查点是客观产物，不是主观判断。**
这一条是白皮书的结构核心，也是对 owner 一次重要纠正的正面承接：**检查点不是"我们设计的关卡"，而是生产流程本身自然要求人类介入的工序产物**。任何真实影视/广告生产线都必然有"定构图、定走位、定时间、定节奏"这四步，人类在这四步天然要做决定，于是对应的工件——分镜图、动作脚本、时间线、节奏轨——天然就是人类要确认的工件。白皮书的任务**不是发明检查点，而是把这四类既有工序的产物形式化**，让它们同时满足：机器可判（能被规则验证）、人类可读（能被一眼看出对错）、可寻址（能被内容指纹定位与失效）。若一个节点设计出来只有机器能判、或只有人能判，它就不是检查点，是实现细节或人工工位。

## 3. 检查点（Checkpoints）通用谱

**先说清这不是清单而是谱**：这 12 个节点按"信息是否还需想象"单调排列，CP1–CP6 是**降维段**（把想象转成规格与工件，成本近零、可 diff、可回归），CP7–CP9 是**生成段**（按次计费，贵的部分），CP10–CP12 是**确定性收口段**（拼装与验收）。人工介入密度不是均匀分布的：CP1/CP3/CP5/CP6/CP12 是**设计内的人工介入点**（`AI视频生产流水线方案.md` P2 验收口径「人工仅出现在 ≤2 个设计内介入节点」在剧集线上需按本谱重新计数，见 §6 门禁），CP2/CP4/CP7/CP8/CP9/CP10/CP11 **默认零人工**（agent 自检通过即推进），仅在触发显式异常条件时上升。

下表每格的五项：**阶段名 / 人类的具体动作 / AI·程序辅助 / 客观验收门禁（可自动判定） / 失败回退**。

---

### CP1 · 意图单（Intent Card）

- **阶段名**：意图 → 一页可寻址的意图卡（含禁区与必须保留物）。
- **人类的具体动作**：写下"要什么"——题材、一句话卖点、必须出现的物件/文字、明确不要的东西（"变形食物""小字堆叠"）、交付规格（竖版/时长/分辨率）。或直接丢 3–5 张参考图说"照这个感觉"。**人类在这一步花的时间应该最多，后面所有步骤的返工率由它决定。**
- **AI·程序辅助**：从参考图与题材生成一份候选意图卡草稿（题材定位、镜头数估算、可用通道清单、预算上限建议）；把禁区映射为具体可判缺陷码（如"食物形变" → `G7_物体恒存`）。
- **客观验收门禁**：意图卡为结构化 YAML/JSON，schema 校验通过；`budget.credit_cap_total` 为整数且非零；禁区条目 ≥1 条且每条映射到已注册的缺陷码（`thresholds.yaml` 内可查，否则拒收）；`deliverable.pixel_map` 与 `encode_contract` 齐备。
- **失败回退**：schema 不通过 → 退回 AI 草稿重建；禁区无对应缺陷码 → **拒收并要求 owner 明确该禁区是否值得为它新建一条门禁**（不许含糊放行）。这是全链唯一允许"必须回到人"的死胡同。

---

### CP2 · 剧本与台词本（Script / Narration）

- **阶段名**：意图 → 分集/分场 → 逐条台词（`narration_segment` 与 `visual_description` 成对）。
- **人类的具体动作**：读一遍台词，删掉不打算说的话、改掉不喜欢的措辞。**人类不判断画面，只判断"这话我说得出口吗"。**
- **AI·程序辅助**：从意图卡生成结构化剧本（DramaClaw 的 `VisualBeat` 结构可直接借鉴：`narration_segment`/`visual_description` 一对一绑定、`time_of_day` 不拼进场景名，见 `dramaclaw-deepdive.md:64-86`）；台词字数 → 预估时长（`hypit-svml-deepdive.md:73` 的 measure 逻辑：按汉字计音节估时长，把"拍多少秒"从剪辑决策变成生成参数）。
- **客观验收门禁**：`Σ estimated_duration` 与目标集时长偏差 ≤2%；台词条数与预计镜头数比值在 `[1.0, 1.5]`（台词过少或过碎都拒）；每条台词不含无法 TTS 的字符集；人名/道具名全部在 cast/props 表中已定义（悬空引用拒绝，沿 v2 §3.2 校验器"引用完整"规则）。
- **失败回退**：超时/不足 → 自动重排台词密度并重报，不改镜头数；悬空引用 → 退回剧本生成，禁止在下游"临时编一个"。
- **注**：DramaClaw 官方三模式中只有 literal（逐行）一条在 CE 主线实装（`dramaclaw-deepdive.md:413-421`），我们抄的是**逐行一拍一镜的节拍结构**，不是它的三模式开关。

---

### CP3 · 分镜表（Storyboard Spec：构图 / 景别 / 运镜 / 时长）

- **阶段名**：剧本 → 逐镜规格表（这是**人类天然要确认的第一件工件**）。
- **人类的具体动作**：看分镜表（或宫格图），对着说"这一镜应该是特写不是中景""这里别推镜头""这一镜砍掉"。**人类管构图，不管像素。**
- **AI·程序辅助**：生成逐镜 `camera{shot, move}`、`action`、`motion`、`refs`、`duration_s`；把意图/禁区字段投影到镜级；为每镜标注需要的通道能力（G5 多身份→必须 API）。
- **客观验收门禁**：每镜五要素齐全（shot/move/duration/action/refs）；`duration_s` ≤ 引擎单段上限（H3 实测 4–15s，`overnight/vpipe/VDL_v2_草案.md` R3）；词锚定合法（`@{}` 引用必须存在于本镜台词内）、跨镜 `during` 必须同场景且编译序在前、循环引用检测（沿 `AI视频生产流水线方案.md` §3.2 校验器七条）；镜头数与 CP2 台词条数一致。
- **失败回退**：任何校验失败 → **退回 CP2/CP3 重生成该镜，不允许带病进入 CP4**。这条是"局部重做优先于整镜重抽"（`AI视频生产流水线方案.md` §2.2 策略 3）在编排层的落点。

---

### CP4 · 构图参考 / 关键帧（Keyframe）

- **阶段名**：分镜表 → 每镜 1–2 张关键帧图（**第二件人类天然要确认的工件**：构图本身就是他要管的东西）。
- **人类的具体动作**：看关键帧图，在图上圈出要改的位置（对应 owner 限定的三种介入形态之二），或写一句话"这里换成侧脸"。
- **AI·程序辅助**：以分镜表 + refs 生图；**身份锚走 VACE/reference 通道**（多参考身份注入必须 API，这是硬实测：Wan-1.3B 无 I2V 权重、LTX 仅首帧条件，`工程方案v3.md:36`）；文字类小字按 v2 §2.3 绕行定稿**改走后期程序渲染字牌**，不进生成模型（G2 实测小字必乱）。
- **客观验收门禁**（全部程序化，零 VLM）：分辨率/比例符合 deliverable；黑图率=0（fp16 NaN 是 V100 已知失败模式）；参考图命中检测——用 DramaClaw 的"在场检测"思路（`dramaclaw-deepdive.md:351-352`：唯一标记色 + 检出态），即 `detected_identities ⊇ expected_identities`；ArcFace 跨身份余弦 ≥ 0.60（统一口径，`AI视频生产流水线方案.md` 表 2-1）。
- **失败回退**：身份未命中 → 先修 refs 再重生，**不重抽视频**；构图不符 → 局部重生成该关键帧（mask 限定），不动其他镜。
- **边界说明**：本层的身份锁止于"在场 + 身份级余弦"，**不是 IP-Adapter 级像素同一性**。DramaClaw 自己在这一点上也是诚实的：`dramaclaw-deepdive.md:388-393` 明确锁①是"把一个 token 塞进 prompt，指望下游模型认出来"、锁③④是"在场检测不是同一性检测"。我们照抄这个诚实边界，不许在白皮书里吹成"跨镜变脸已解决"。

---

### CP5 · 动作脚本（Blocking：走位 / 姿态序列）

- **阶段名**：分镜表 → 确定性动作描述 + 可执行姿态序列（**第三件人类天然要确认的工件**：人本来就要管演员走位）。
- **人类的具体动作**：读动作脚本："他应该先伸手再拿杯，不是一次到位""走两步就停"。**人类管动作语义，不管渲染。**
- **AI·程序辅助**：把 `motion{walk:2steps, gesture:pickup}` 编译成姿态序列——直接采用 ToonFlow 3D 导演台的 `mannequin` schema（`cheap-draft-and-programmatic-tools.md:57-59`：内置 16 关节人偶、`objType:"mannequin"`、`pose` 为相对父关节的 XYZ 欧拉角弧度、`{"objectId","joint","frames":[{time,rotation}]}`、`hiddenParts` 遮挡裁剪、关键帧可导出为图/视频节点）。这份 schema 与 MimicMotion 的 DWPose 输入、Blender armature 是同一类中间表示，一份数据三端通吃。
- **客观验收门禁**：姿态序列关节名合法（16 关节穷举）；帧时间单调；帧数 ≤ 上限（MimicMotion 上限 72 帧 @576×1024，`cheap-draft-and-programmatic-tools.md:219`）；骨长恒定（rotation-only，禁 scale）；`motion.speech=full-body` 时必须存在独立口型层路径（否则此镜降级拆为"无对白行走镜 + 近景对白镜"，**分镜层规避，禁止质检环节自动改景别**——`AI视频生产流水线方案.md` §3.3 明文）。
- **失败回退**：姿态编译失败 → 退回 CP3 改 action 描述，不许让 MimicMotion 自由发挥；72 帧装不下 → 分段 + progressive latent fusion，**拼接缝必须登记为 `known_cuts`**（见 CP11）。

---

### CP6 · 时间线与节奏轨（Timeline + Rhythm Track）

- **阶段名**：分镜表 + 台词时长 + 动作时长 → 单一帧域时间线（**第四件人类天然要确认的工件**：节奏是剪辑的核心工作对象）。
- **人类的具体动作**：在时间线预览上拖动段落、改镜头时长、调整停顿，说"这里别停""这段要压到 3 秒"。
- **AI·程序辅助**：建立**唯一收敛口**——语义锚点只投影一次为帧域，之后全链复用同一 Timeline。直接抄 hypit 的三段机制（`hypit-svml-deepdive.md:25`：`pipeline:Normalize` 归一到同一 30fps 时钟域 → `whisperx:SemanticTake` 把音频词级时间对齐回 Script 的某个 Segment → `time:Timeline` 顺序装配）；此后字幕/B-roll/贴纸只引用 `{story.selection.xxx}`、`{story.moment.xxx}`、`during={story.segment.x}`，**组件自己不做找帧**。
- **客观验收门禁**：Σ shot.duration == 集时长（±1 帧）；字幕段与音轨词级时间偏差 ≤ 40ms；无时间轴循环引用；音频先入引导（sound lead-in）帧数符合声明；节奏轨上无长度 <0.8s 或 >12s 的段落（warn-only 起，阈值来自 `thresholds.yaml`）。
- **失败回退**：时长不守恒 → 自动重算配音时长并回填（shuohao 式确定性折算）；段落过长过短 → **上升人类一次，带三个候选方案**（对应 `INTENT.md:88` 的"给参考"介入形态），不允许自动改。
- **这条检查点是白皮书与既有资产对接的关键**：owner 的模板线诉求（`INTENT.md:39`「通过类似 hypit 的 SVML 标准化描述后就形成模板，换人物/台词确定性生成」）在 vpipe 里的落点就是这个 Timeline + 槽位，而不是 shot.json。

---

### CP7 · 草稿视频（Draft Clip）

- **阶段名**：分镜表 + 关键帧 + 姿态 → **廉价本地草稿片**（构图/节奏/动作预演，不是成品）。
- **人类的具体动作**：默认**不看**。仅当触发"冷启动保护"（新模板/新角色/新生成模型的前 N 条）时抽看。`AI视频生产流水线方案.md` §4.2 L5 行明确写了这条例外。
- **AI·程序辅助**：本地 LTX-2B distilled（fp16，8 步，实测 76.7s/条、0 积分、42/42 全成，`工程方案v3.md:35`）或 Wan2.2-TI2V-5B（`--convert_model_dtype` 降 fp16 + SDPA 兜底；仓内实测 Q8 档 212–214s/33 帧、23.7GB，`AI视频生产流水线方案.md:129`）。**bf16 与 fp8 一律不碰**：`torch.cuda.is_bf16_supported()` 要求 `major >= 8`，V100S 是 major 7（`cheap-draft-and-programmatic-tools.md:187`）；flash-attention 官方 README 只列 Ampere/Ada/Hopper，Volta 不在支持列表（同文件 :188）。
- **客观验收门禁**：黑场/单色占比 ≤50%；时长偏差 ≤2%（L0 预检已实装，拒收 exit 4）；无 NaN/黑帧；帧率/分辨率符合档位声明。**草稿层不做 aesthetic 判定**——它存在的唯一理由是给择优器东西可打。
- **失败回退**：L0 拒收 → 同 seed 重跑一次（零成本）；仍败 → 换 seed 或降档；连续两镜同因失败 → 判为通道问题，停止草稿生成并上升。

---

### CP8 · 择优（Selection / Best-of-N）

- **阶段名**：N 个草稿候选 + 硬校验指标 + judge 分数 → 选 1 个进精修。
- **人类的具体动作**：默认不看。仅当 judge 间分歧 > δ 或与硬校验方向矛盾时看（`AI视频生产流水线方案.md` §4.2 L3）。
- **AI·程序辅助**：分两层，**这两层不可混**——① **相对线**（BoN 候选排序，只排序不设绝对通过线）；② **绝对门**（成片放行，QCReport 层）。硬校验承重、judge 只排序、矛盾上升人（`AI视频生产流水线方案.md` 第四章开篇）。
- **客观验收门禁**：候选集内 top-1 在硬校验向量上 Pareto 支配（无单项比 top-2 差且总分更低）；judge 相对线只决定次序；**任一 A/B 组否决缺陷存在 → 候选直接出局，不进 top-k**。
- **失败回退**：无候选达标 → 升一档（草稿 → API 草稿 → 精修），并记录这是"结构性困难镜"；单镜重试上限 2 次，超限转人工工单。

### CP9 · 终稿渲染（Final Render）

- **阶段名**：选中的构图/关键帧/动作/时间 → **精确渲染**（贵的那一层，owner 明示"让 seedance 2.5 这种专注在最终渲染"）。
- **人类的具体动作**：默认不看。只有在风格/表演类判据（gate=human）上才看，且只看被判 flag 的那几镜。
- **AI·程序辅助**：调精修通道，出 768P+ 含音轨的终稿；局部返修优先于整镜重抽（圈选 mask → 先编辑后运动）。
- **客观验收门禁**：**参数级**复现留痕（提交参数、seed、指纹落盘一致）；不做像素级 md5 承诺（owner 已明令废止该表述）。成本闸门单点：每镜 `credit_cap_per_shot`，超限 exit 3（`工程方案v3.1.md` §6.3 实证——首批 34 条 `submit_error` 被 DTO 校验在扣费前拦截、0 损失）。
- **失败回退**：质量缺陷按类型路由（身份→回 CP4 修 refs；动作→回 CP5 修姿态；构图→回 CP3/CP4）；**任何回退都不得跳过 CP6 直接换时间**，因为时间错了构图必然错。

---

### CP10 · 字幕与音轨（Subtitle / Audio）

- **阶段名**：台词 + 时间线 → 配音 + 字幕 + 混音。
- **人类的具体动作**：听一遍音色与语速；如不满意给一个音色参考（voice_id），不改台词。
- **AI·程序辅助**：TTS 走 StepFun `stepaudio-2.5-tts`（默认）或 Design seedaudio（备用）；字幕走 ASS 硬渲染 + whisper CER 双口径校验。**量产前先克隆统一音色性别**——已实测教训：StepFun 磁性男声 × 女性角色 = 性别错配（`工程方案v3.1.md:53`）。
- **客观验收门禁**：ffprobe 时长守恒（avatar 线 = ceil(音频秒)）；ASS 逐字硬校验零错字；whisper CER small/medium 双口径 ≤5%（同音字以 pinyin 归一口径分析，不凑数，`INTENT.md:89`）；响度 −16 LUFS；数字只在字幕里、不在画面里。
- **失败回退**：CER 超标 → 优先改分句（TTS 与字幕共用同一分句源），不改词；音色错配 → 换克隆参考，不逐条手改。

---

### CP11 · 合成（Compose）

- **阶段名**：所有片段 + 字幕 + 音轨 → 成片。
- **人类的具体动作**：默认不看。
- **AI·程序辅助**：ffmpeg 子进程 + MoviePy v2（确定性梯度顶端）；字幕/花字/排行榜类镜头走 HyperFrames（Apache 2.0、无 per-render 费用，`hypit-svml-deepdive.md:19,99`）；所有拼接硬切点**登记 `known_cuts`**。
- **客观验收门禁**：ffprobe 校验（总时长 ±1s、竖版 1088×1920、h264+aac）；切镜数 == 分镜表镜头数；黑场占比；**拼接切点全部在 `known_cuts` 白名单内登记**——否则 J6v2 的 `temporal_swap` 规则会对同人物同构图的硬切误报（实测后向重入相似度 0.9784 远超 `swap_single_back_min=0.85`，`工程方案v3.1.md:170`）。这一条已在 v3 首批落地（`deliverables_v3/V3_BATCH1_WORKER_A.md` C 组：`dh_final` 13.917s 拼接切点 swap 豁免通过）。
- **失败回退**：切点数不符 → 退回定位是哪一镜多/少切；编码不达标 → 只重跑合成（零 API 成本），**这是全链最便宜的一次修复**。

---

### CP12 · 质检与成片（QC Report + Master）

- **阶段名**：成片 + 剧本 + 各镜 QCReport → 放行/驳回 + 成片交付。
- **人类的具体动作**：三件事，且只做这三件——① 看**闸门标出的灰区队列**（不是全片）；② 看 D 类缺陷（物理/时序/叙事/整体观感），这是允许保留的人工工位；③ 签字或驳回。
- **AI·程序辅助**：五层质检（L1 确定性程序 / L2 专用小模型 / L3 judge 多模型合议 / L4 整片级时序叙事 / L5 分流人审）。**成片分 = 0.7×镜头分均值 + 0.3×最差镜头分**（短板惩罚，`AI视频生产流水线方案.md` :162）；任一镜头存在 A/B 组否决缺陷 → 成片门直接不通过。
- **客观验收门禁**：
  - 成片绝对门：judge 标定分 ≥70（≙ 人评 7.0/10），且**必须是人评锚定后的映射值**——70 不是拍脑袋数，是映射曲线上人评 7.0/10 对应的 judge 分（`AI视频生产流水线方案.md` §2.3 第 3 条）。
  - A 组：程序规则，召回 ≥99%、误报 ≤1%。
  - B 组：专用小模型，召回 ≥95%、误报 ≤15%；LSE-D 硬门仅特写/近景，全身镜头降 warn-only。
  - C 组：VLM judge，类内召回 ≥80%、误报 ≤15%，**judge 缺陷不允许自动否决**。
  - D 组：**默认 warn-only，不做自动否决**（物理类 GPT-4V ROC-AUC≈53≈随机、Gemini 58；时序类 TempCompass 人类 96.7–100 vs 视频 LLM 27–41）。
  - 人工上升率 ≤20%（周复核误杀/漏放并回滚权重）。
- **失败回退**：任一硬门不过 → **按缺陷类型路由回具体 CP**（身份→CP4，动作→CP5，节奏→CP6，字幕→CP10），**不允许成片级重抽**；重试 ≤2 轮仍不过 → 人工工单并把该镜标记为"结构性困难"，进金标扩样队列。

---

**谱的使用规则**（三条，防止它退化成官僚流程）：
1. **CP 是工件的位置，不是审批的次数。** 一个人可以在一次交互里同时处置 CP3/CP5/CP6（agent 把三张图 + 时间线预览打包成一份 `CONFIRMATION` 式清单），owner 的 `INTENT.md:73` 明确要求"人工确认项必须显式列出、集中打包，不许碎片化打扰"。
2. **默认零人工的 CP 不许因为"保险"而加人。** 加人必须回答"补的是哪个已知失效模式"，答不出就不加。
3. **每个 CP 的门禁都必须能被一条命令判定。** 判不了就不是门禁，是文档。

### T0 · 确定性层（零生成成本）

- **通道**：ffmpeg 子进程 + MoviePy v2；HyperFrames（HTML+`data-*`，headless Chrome 逐帧 seek + ffmpeg，Apache 2.0，171 blocks + 223 components catalog）；Blender 无头（`blender -b scene.blend -a -s <start> -e <end> -o //out/####`）。
- **选择依据**：① 同输入像素级同输出，是**唯一能承诺像素级复现的层**；② 零调用费（`hypit-svml-deepdive.md:76` 实测字幕/排行榜/B-roll 动效全是纯 HTML/CSS 组件）；③ HyperFrames Apache 2.0 无商用门槛，而 Remotion 明确「not allowed to copy or modify Remotion code for the purpose of selling… your own derivate」——owner 终局目标是订阅服务，Remotion 作对外底座踩条款（`cheap-draft-and-programmatic-tools.md:337`）。
- **客观形态**：字幕/花字/排行榜/片头/数据可视化/运镜矢量/深度图/遮挡 mask。
- **单条成本**：**¥0 + CPU 墙钟**。
- **该层门禁**：ffprobe 全项；**把 CRADLE 六道硬校验（分辨率/帧率/时长/黑场/字幕≠台词/切镜数）挂到 HTML 合成产物上**——这一件是一天工作量、立刻有价值，因为合成层是目前唯一 100% 良率、最该被守住的那一段（`cheap-draft-and-programmatic-tools.md:371`）。像素级回归用例 ≥3 个。

### T1 · 分镜草图 / 关键帧层（本地图像）

- **通道**：VACE-1.3B（参考图注入 + 局部重做，Apache-2.0，1.3B 约 16GB@512×512×81 适配 32GB 卡）；Qwen-Image-Edit-2509 GGUF / FLUX.1-Kontext dev（12B 社区约 24GB fp16 单卡可容）作备。
- **选择依据**：VACE 把"一致性注入"与"反馈局部重做"统一到同一个 mask 通道——**这是 CP4 的局部返修能力来源**，一条通道两用，不重复建设。20B 级编辑器**无 NVLink 禁模型切分，无例外**（`AI视频生产流水线方案.md` §2.1 纪律）。
- **客观形态**：每镜 1–2 张关键帧 PNG + 身份参考图。
- **单条成本**：**0 积分**；墙钟量级待实测（T9 为此设时间盒：GGUF 档黑图率 ×5 prompts = 0 且显存 ≤30GB 才入产线）。
- **该层门禁**：黑图率 = 0；在场检测（`detected ⊇ expected`）；ArcFace 逐身份余弦 ≥ 0.60；文字类一律走后期字牌（G2 小字必乱，绕行定稿）。

### T2 · 廉价草稿视频层（本地 V100S）—— **owner 的"廉价本地模型先形成草稿"**

- **通道**：**LTX-Video 2B distilled**（首选，★★★★★，owner 已跑通）→ Wan2.2-TI2V-5B（次选，★★★★☆）→ CogVideoX-2B（兜底，唯一官方推荐 FP16、4GB 起）。
- **选择依据**：不是"便宜"，是**"SM70 上真能跑且实测过"**。矩阵里其余全部出局：Wan2.2-A14B 官方门槛 ≥80GB，双卡无 NVLink 不能 TP（★☆☆☆☆）；HunyuanVideo 需 60GB 最低；Mochi 官方栈 60GB；CogVideoX1.5-5B 官方速度基准就是 A100/H100 量级。**决定性约束是精度**：`torch/cuda/__init__.py` 的 `is_bf16_supported()` 要求 `major >= 8`，V100S 是 major 7；而 HunyuanVideo-1.5 / CogVideoX1.5-5B / Mochi **全都默认 bf16**（`cheap-draft-and-programmatic-tools.md:187,196,199,202`）。
- **客观形态**：480×704 或 480×832、16fps 的构图/动作/节奏预演片。**它不是交付物。**
- **单条成本**：**0 积分**。LTX-2B 76.7s/条（15.2× 实时）；Wan2.2-5B Q8 212–214s/33 帧。
- **该层门禁**：L0 预检（黑场 ≤50%、时长偏差 ≤2%、拒收 exit 4）；黑帧率 0；**只做择优不做 aesthetic 判定**。
- **ROI 的诚实算法**：`ROI = (它替精修层挡掉的镜头数 × 精修单价) − 本地墙钟成本`。这个不等式必须用 owner 自己的真实单价跑一遍才知道拐点在哪，**没有任何现成工具能算**（`cheap-draft-and-programmatic-tools.md:347`）。若 LTX 能挡掉 30–50% 镜头，这层就成立；挡不掉，它就只是多烧一遍时间。

### T3 · 动作与口播层（本地 + 极便宜 API）

- **通道**：**MimicMotion**（全身动作，官方 V100 验证、16GB、72 帧 @576×1024、confidence-aware pose guidance + regional loss amplification 专治手部扭曲）+ **EchoMimicV3**（特写口型，1.3B/12GB，官方测试卡含 V100 16G，talking head 5 步）+ **可灵 Lipsync / 本地 LatentSync·Wav2Lip**（全身对白的独立口型层）+ **Vidu avatar**（口播主体，API 但极便宜）。
- **选择依据**：MimicMotion 是**唯一同时满足「官方 V100 验证 + 16GB 显存 + 动作可编程」**的模型（`cheap-draft-and-programmatic-tools.md:226`）。可编程是关键：输入是姿态序列不是文本，所以**动作先在确定性层被指定（CP5），再交给渲染**。EchoMimic 反过来——它是音频驱动，动作由音频定，**你无法指定"手要伸向第三个按钮"**，所以它解决口型不解决动作。
- **客观形态**：姿态驱动的动作层片 + 独立口型层 + Vidu avatar 口播片（540p=618×836 / 720p=826×1114）。
- **单条成本**：MimicMotion **0 积分**但**慢**——72 帧 20 分钟@4090，V100S 只会更慢 → **只能对"需要指定动作的少数镜头"跑**。Vidu avatar **1 积分/秒**（30s 口播 ≈30 积分），是本体系内最省路径。
- **该层门禁**：MediaPipe 手部检测（J1 手部漏 2/5 是 B 类召回上限的短板，`工程方案v3.1.md:264`）；SyncNet LSE-C/D（**仅特写/近景硬门，全身镜头 warn-only**）；口播线的时间窗须登记 `--profile avatar_talk`（J6v2 ghosting 规则在口播自然低运动平台上 2/2 误报，实测 in_med=0.71–1.64，`工程方案v3.1.md:169`）。

### T4 · 精修层（API，按秒计费）

- **通道**：**H3-Max（现役默认，同价 4 倍速、42/42 零失败、G6 运镜语义与 G3 计数个例反超）**；回退 H3（两类场景：强风格指令镜头——H3-Max 有风格漂移实测 G8-35 水墨→彩色工笔；面部相似度优先的定妆类镜头——H3-Max 系统性轻度美颜化）；可灵 3.0 / 2.5-turbo 待核价后作并行池。
- **选择依据**：本地路线**做不出终稿**——LTX 480p 无声无 I2V，缺口要靠 RIFE 插帧 + Real-ESRGAN 超分补，而这两个环节至今标注"调研材料无 V100 一手实测，E12 验证"。API 的钱买的是 768P、音轨、多参考身份、0 本地 GPU 占用、比本地 Wan 快 17×（`工程方案v3.md:127`）。
- **客观形态**：768P+ 含音轨的终稿片段。
- **单条成本**：**280 积分/5s（56 积分/s）**；标准档 120s 单集 6,720 积分（含重试 8,736）。
- **该层门禁**：积分双拦截（"已耗 > 上限"、"已耗 + 预估 > 上限" → exit 3）；DTO 白名单校验**先于扣费**（已实证：首批 34 条 submit_error 零损失）；**参数级复现留痕，不承诺像素级**；T2V 必须显式 `image_mode="text-to-video"`（default=reference 且零参考图即 500）。

### T5 · 终稿/精修上限层（owner 点名的 Seedance 2.5 等）

- **选择依据**：owner 原话"让 seedance 2.5 这种专注在最终渲染"。技术上的对应优势有三：① 参考驱动（up to 50 reference inputs）；② **Draft 机制**——先出 480p 样片（token×0.6），凭 `draft_task.id` 出正式片时平台自动复用 model/seed/ratio/duration/camera_fixed「保证视频关键要素一致」（ID 有效期 7 天）。这是**平台侧的官方版"草稿抽卡→定向出片"**，与我们的 CP7→CP9 结构天然同构，是本白皮书最值得优先验证的一条外部机制。
- **客观形态**：高保真终稿片段（768P/1080P，含音轨）。

- **回退方案**：Seedance 未通则 T5 退化为 H3-Max 独占（已实测可交付），白皮书结构不变。

### M1 · 骨架（W3–W5）

- **目标**：CP1–CP6 + CP10–CP11 的**纯确定性层**全部跑通并接上现有门禁——这段不花 API 积分，是全谱里最便宜也最该先做的一段。
- **关键交付物**：
  1. CP2 剧本 schema + 时长守恒校验（Σ estimated_duration 偏差 ≤2%）。
  2. CP3 分镜表 schema + 校验器七条（引用完整/词锚定/跨镜 during/循环引用/值域/时长守恒/质检阈值一致性）。
  3. **CP5 `blocking` 字段定义**（采用 ToonFlow `mannequin` 16 关节 Euler 弧度 schema），用 Blender `export_scene`/armature 导出做一次端到端连通性验证。**本周只做 spec 不做训练。**
  4. **CP6 单一帧域 Timeline**（Normalize → 词级对齐 → Timeline 三段，收缩自 hypit），模板线槽位从这里开始。
  5. CP11 合成层硬校验挂载（把 CRADLE 六道硬校验挂到 ffmpeg/HyperFrames 产物后），像素级回归用例 ≥3。

- **回退**：Timeline 若两周内不收敛，退化为"单一 timeline JSON + 所有下游只读它"的最笨实现，先保证收敛再谈优雅。

### M2 · 试跑（W6–W9）

- **目标**：出**第一条完整走通 12 个 CP 的 30s 样片**，并把人工介入点实测计数落定。
- **关键交付物**：
  1. T2 草稿层接入（LTX-2B 主力，Wan2.2-5B 对照），CP7→CP8 全通。
  2. T3 动作/口播层接入（MimicMotion 少数指定动作镜 + Vidu avatar 口播段 + 口型层）。

  4. **CP12 四维判定上线**：缺陷维（E10 已有）+ 规格服从维（新，纯规则）+ 审美维（先 warn-only）+ 合规维（先 warn-only）。
  5. **人工介入点实测计数**：CP3/CP5/CP6/CP12 四处，设计内介入次数 ≤2（沿 v2 P2 验收口径），其余 CP 零人工。
  6. 成本台账首版：每 CP 的墙钟/币种/金额。
- **验收门禁**：① 一条 30s 含数字人段样片 + QCReport(1.1) + eval ACCEPT 三件齐（TASK.md D-1）；② 规格服从维 A 组召回 ≥99%、误报 ≤1%；③ 人工上升率 ≤20%；④ 单集成本 ≤ 标准档 6,720 积分 ×1.2；⑤ `known_cuts` 漏登记 = 0。

### M3 · 扩张（W10–W12）

- **目标**：从"一条样片能跑"扩到"一批能稳"，并把 CP 级回归资产固化。
- **关键交付物**：
  1. **CP 级夹具库**：每个 CP 至少 3 条 fail + 2 条 pass 的回归夹具（照 G7/金标的建库方式）。这是白皮书相对 v3 的核心增量——v3 的夹具在"生成层"，白皮书的夹具在"工序层"。
  2. **收敛曲线**：每 CP 的 `residual_count / fixed_count / new_failures` 逐轮记录（抄 DramaClaw `convergence_log.py`，`dramaclaw-deepdive.md:504`），让"修复循环是否收敛"成为可测数字。
  3. **人工否决一等化**：每次人工 accept/veto 落 append-only 审计表并回写主行汇总位（抄 `emit_human_override.py`，`dramaclaw-deepdive.md:466`）。owner 已明示人工确认不可代签，那就把它变成**资产**而不是负担。
  4. **三版本字段强制随行**（`registry_version` / `prompt_version` / `spec_version`）。
  5. 模板线打通：槽位替换 → 只失效受影响 CP。
- **验收门禁**：① CP 级夹具库建成，各 CP 门禁在 fail 组拦截率 ≥90%；② 连续 3 条样片 CP 级零未声明回归；③ 改 30 镜中的 3 镜，实际重跑 ≤3 镜（其余命中指纹缓存，且**含镜头重排不伪失效验证**）；④ `prompt_version` 缺失项 = 0。
- **主要风险**：CP 级夹具库工作量被低估（12 个 CP × 5 条 = 60 条，按 G7 的建库节奏是数天量级，不是数小时）。
- **回退**：夹具库按 CP 优先级分批建——先 CP11/CP12（最便宜、最该守），CP7/CP9 的生成层沿用现有金标不重建。

## 7. 非目标

1. **不做"让人满意的视频"，只做"可交付的视频"。** 质量上限由模型档位给出，不再往上追。成片门 = 零严重缺陷 + 覆盖率下限 + 人评 7.0/10 等价分，不设"惊艳"指标。
2. **不做全自动到 0 人工。** 人类介入点是**设计的一部分**（CP3/CP5/CP6/CP12），不是待消灭的缺陷。owner 限定介入形态只有三种（文字反馈 / 圈改 / 给参考），本白皮书不引入第四种。
3. **不做时序/物理/叙事的自动否决。** D 组默认 warn-only，这是当前技术条件下的诚实定位（7 路 judge 时序召回全零；物理类 ROC-AUC≈53≈随机）。不许在 D 组上写"自动拦截"字样。
4. **不做 3DGS / 空间重建 / 角色 LoRA 训练。** Director World 的实现层需 GPU+CUDA+Node.js 且未进 release；owner 的 2×V100S（SM70/仅 fp16/无 NVLink）跑不动主流 3DGS。只抄它的**契约层** JSON。LoRA 训练在 SM70 fp16 有 NaN 风险且时长无调研数据，不进产线依赖。
5. **不做通用视频生成平台。** DramaClaw ELv2 明禁托管 SaaS、hypit 非 Apache（多租户/商业再分发/去 LOGO 三条限制，`hypit-svml-deepdive.md:19,80`）。本白皮书的目标是**自用产线 + 卖成片**，不是卖工具。多租户/认证/计费/配额/分布式 task backend 是**未来订阅服务的题**，不是本白皮书的题。
6. **不追求覆盖全部模型/全部供应商。** 通道池只保留"已核价 + 已实测 + 有降级路径"的三条主通道 + 一条待核价通道。新供应商接入判据固定：先跑 1 条小额测试片，核价与限流落 evidence，才准进 tier 表。
7. **不做无头浏览器/GUI 商业软件依赖。** AE（需正版 + Windows/macOS + GUI 常驻）、DaVinci Resolve 免费版（21.1 后 Scripts 菜单已无 `.py`）、TouchDesigner（无无头渲染承诺）都不进 anolis-gpu-01 产线。mcp-for-blender 的任意 Python 执行能力只用于**人机共驾的预演台**，不作无人值守批处理的唯一入口。
8. **不重训 judge、不用人评做 judge 标定（12 周内）。** 70 分的人评锚定（120 片段）是 P3 级投入，M3 结束时仍列为"未做"。在此之前，70 只作为 warn 阈值与人工队列排序依据，**不作为自动放行的绝对门**。

## 8. 与现有项目的整合方式

**结论：扩展（extend），不是替代，也不是共存。** 三句话说清：

```
白皮书 = 上层规范（生产函数 + 12 CP 谱 + 5 模型层 + 门禁集）
   │  投影（不变的部分不重写）
   ├─→ VDL v2 = 编排语言（已有草案，v1 契约冻结不破坏）
   │      ↑ CP1–CP6 的工件即 vdl_package 的 intents/shots/post_ops 段
   ├─→ vpipe = 执行与验收实现（SPEC.md 契约冻结不动）
   │      ↑ CP7/CP9 = gen_local/gen_api；CP11/CP12 = qc_orch + report
   └─→ thresholds.yaml = 唯一阈值来源（全部 CP 门禁数值的落点）
          ↑ 白皮书新增 CP 级段，v1 段一字不改
```

**三条整合铁律**：

1. **v1 契约与 E10 基线零改动。** `TASK.md:15` 已定"v3 只增不破"。白皮书的全部新增走 **v2 并行 + 文件级版本判定**（`schema_version` 值而非目录级，防错放），v1 引擎只见过投影产物、零修改。E10 的 R=1.000/FPR=0.250/F1=0.9143 是**回归基线**，任何改动后必须位级一致才能合入。
2. **交付物三件套的归属明确**：
   - **Checkpoint schema** → 新增 `contracts/v2/checkpoint.schema.json`，与已有 `vdl_package` / `shot_v2` / `qc_report_v2` 并列，成为 v2 的第四份契约。
   - **Model tier 表** → 落成 `engine.channel` 枚举的**唯一来源**（现在枚举写在 `VDL_v2_草案.md` §3.2 #4 的文档里，是漂移风险；落成配置后，R2 校验规则才有稳定的枚举可依）。
   - **判定门禁集** → 全部数值入 `thresholds.yaml` 的新 CP 分段；`thresholds.yaml` 版本从 v3 升 v4，**sha256 留痕同步更新**（G0-3）。改动走既有修改规程：重跑 eval、退化则回滚。
3. **"旧代码可丢弃"在本白皮书里的具体边界**：丢的是**结构**（单镜头合议为顶层、画布交互层、Seedance 锁存），留的是**资产**（阈值机制、契约、夹具、金标、判官协议、G0 四门）。判断标准只有一条：**这条资产记录的是一个可复算的结论吗？** 是则留（可重写实现），否则丢。SPEC.md §6 的"重生成 = 只读 SPEC + contracts + eval"规程因此继续有效——白皮书只是让 SPEC 变厚，不让它失效。

**白皮书对 owner 的价值，一句话**：它把"廉价草稿 + 高端精渲"从一句选型偏好，变成了一条**每个工序都有客观工件、每个工件都有可判定门禁、每个门禁失败都指向明确回退点**的生产链——从而使"无人干预但平庸可接受"成为一个可以被验收的工程目标，而不是一个愿望。
