# 金标扩样方案（TASK.md D-3 之一：扩样方案成文）

> 编制：2026-10-09｜状态：方案已成文，执行由 m3-golden-expansion 工作流承担
> 依据：白皮书 §3.6（金标扩样需求）+ §6 M3-W11 + thresholds.yaml `J6_detectors_v2.promote_criteria` 缺口分析

## 1. 为什么必须扩样（缺口实证）

现行金标 40 条（A16 注入/B12 意图/C12 干净，2026-09-29 生成）的三个结构性缺口，全部有实测证据：

| 缺口 | 现状 | 导致的实证后果 |
|---|---|---|
| **时序四类 n=2/类** | freeze/swap/ghosting/flicker 各 2 条 | J6v2 时序 clip 召回 0.625 < promote_criteria 0.85，单条翻转即 50% 摆动——转正否决层的门槛无法达达（工程方案v3.1 §3.3） |
| **无口播数字人正例** | C 类 12 条全为 H3 叙事短片 | J6v2 在口播素材上 2/2 误报（ghosting 规则把自然低运动平台读成混叠，工程方案v3.1 §3.4 机理 1）——金标无标可量，豁免只能走上游声明制 |
| **无 API 产物乱码文字正例** | G2 注入为像素化/乱码的老形态 | 营销线 shot_05 实测生成侧标签乱码（J1 identity_drift 检出）——当前金标无此类正例，J1 的 G2 召回无标可量 |

## 2. 扩样构造方案（确定性注入，沿用金标既有协议）

构造工具链：`overnight/vpipe/tools/regen_fixtures/`（2026-10-07 入库的确定性伪影注入生成器，19 片夹具重建同款纪律：注入签名帧级自检、sha256 留痕、manifest 登记）。

### 2.1 新增样本总表（目标 40 → 52，+12）

| 组 | 类别 | 条数 | 构造方式 | 验收判据 |
|---|---|---|---|---|
| A 组 | 时序四类补足（freeze/swap/ghosting/flicker 各 +3 → n=5/类） | 12 | 从 C 类干净片按 2026-09-29 同款注入配方构造（注入参数从原 8 条 A 类时序的 manifest 复刻，seed 换新）；每条过注入签名帧级自检 | 注入生效（签名核验 100%）+ 三 judge 盲测检出率 ≥ 基线同类 |
| B 组 | 口播数字人意图 2 条（唇形不同步/口型与台词错位） | 2 | 用 Vidu S2 avatar 真实生成 2 条口播片（参考图+音频），其中 1 条音频故意错位 0.5s 制造不同步 | judge 检出 + 人工复核确认意图成立 |
| C 组 | 口播数字人干净正例 3 条 | 3 | Vidu avatar 正常口播（语速/停顿自然，覆盖 540p/720p 两档） | judge 零误报目标（当前 J6v2 在该类 2/2 误报，豁免后应归零） |
| C 组 | API 产物标签乱码正例 2 条 | 2 | H3-Max 生成带文字标签的产品图（已知会乱码的 prompt 形态，营销线 shot_05 实证），画面其他部分干净 | J1 identity_drift/G2 检出 ≥1/2 |

### 2.2 预算与凭据

| 项 | 预算 | 通道 |

| judge 盲测 | 0 积分（glm8 API 走 Zhipu key；omnijev/videochat3 本地卡 0） | 卡 0 跑前复测、等位不抢卡 |
| 注入构造 | 0 积分（ffmpeg 本地） | — |

单笔最大 560 积分 < 300 元等值线内，无需请示。

### 2.3 盲测与复核流程

1. **构造**：按 §2.1 生成 12 条新样本 + 更新 manifest（A28/B14/C14=56？不——目标 52：A28/B14/C10... 按 §2.1 表逐组计数，最终 manifest 以实际入库为准，failures 必须为 0）
2. **盲测**：新样本过三 judge（glm8/omnijev/videochat3，隔离独立判定，六字段协议）；判官不知新样本标签
3. **E10 复核**：扩样后金标全量跑 `eval_run.py`——准入线（召回≥0.90/FPR≤0.30/F1≥0.85）必须仍 ACCEPT；若工作点漂移，按 thresholds.yaml 修改规程（说明+留痕+owner 知悉）处理，**不许放水准入线**
4. **J6v2 复测**：时序四类 n=5 后重跑 promote_criteria（召回≥0.85 且 FPR≤0.15）——达线则出「时序哨兵转正评估」，未达线如实记录仍 signal_only
5. **冻结**：新 golden manifest + 判官输出 + eval 留痕三件套入 `overnight/数据/golden/`（数据域，按金标纪律不入 git）；`eval/golden_manifest.json` 同步更新并在 worklog 登记

| 风险 | 处置 |
